# Defects of the reference tools that were not ported

netbox-omnisync was written from three existing tools. A behaviour of a
reference tool that turned out to be a defect is fixed here, not reproduced;
each fix is pinned by a test that was seen failing on the ported behaviour
first. A difference this causes on a first run against an existing NetBox is
an intended one.

## netbox-switch-sync (Cisco, FortiOS)

| Defect in the reference | What netbox-omnisync does | Test |
|---|---|---|
| With pruning, an interface absent from the switch was deleted even when it carried an IPv6 address; NetBox deletes an interface's addresses with it, although IPv6 is never collected. | The interface is kept, with a warning. | `network::diff::tests::interface_carrying_an_ipv6_is_never_pruned` |
| The interface protected as "the one carrying the primary IP" was the first address equal to the primary one, whatever its VRF: with the same address in two VRFs, the wrong interface could be kept and the right one deleted. | Every interface carrying an address equal to the primary one is kept. | `network::diff::tests::every_interface_that_may_carry_the_primary_ip_is_kept` |
| An unassigned NetBox address with the same host was adopted whatever its VRF, then moved to the device's VRF, ahead of the unique-table check. | An unassigned address is adopted in its own table only; otherwise a new address is created. | `network::diff::tests::unassigned_ip_of_another_vrf_is_not_adopted` |
| The warning about an address held by another device printed `None` when that address had no interface. | The holder is named alone. | `network::diff::tests::ip_held_elsewhere_without_an_interface_names_its_holder_only` |
| A neighbour name announced with spaces around it was looked up as is, and never found. | The trimmed name is looked up. | `network::cables::tests::a_name_announced_with_spaces_around_is_looked_up_trimmed` |
| A port that hears itself over LLDP or CDP (a loop) raised an unhandled exception. | No cable, the local end is protected, and a warning names the port. | `network::cables::tests::a_port_that_hears_itself_gives_no_cable_and_keeps_its_own` |
| `domains` written as a string gave one domain per character; a `netbox` section that is not a table, a non-text `key_file`, an unreadable or non-UTF-8 configuration file each ended in an unhandled exception. | Each is a configuration error naming the file and the key. | `network::inventory::tests` |
| Starting the progress row of a device twice left the first row on screen until the end of the run. | One row per device. | `progress::tests` |
| A switch with CDP turned off failed its whole collection (the `%` answer was taken for a refused command), while LLDP turned off did not. | No CDP neighbour, like LLDP. | `parsers::ios::tests::cdp_disabled_is_empty` |
| A Nipper report cut short was read as a switch with fewer ports: with pruning, the others would have been deleted. | The report is refused. | `parsers::nipper::tests::a_report_cut_short_is_a_failure` |
| An empty `cmdb/system/interface` answer of a firewall (`"results": []`), or one whose every interface is ignored, gave a firewall without interfaces: with pruning, every interface NetBox holds was deleted. An empty monitor was accepted the same way. | The collection fails, naming the call. | `parser::tests::no_interface_is_never_an_answer`, `parser::tests::every_interface_left_out_is_never_an_answer`, `collect::tests::fortios_without_any_interface_fails_collection` |
| A firewall read refused by the API (`401`, `403`, a redirect) was reported as `<call>: HTTP <status>`, without the firewall it came from; and a login that opened no session (a wrong password, a locked account, and any login on `/logincheck` from FortiOS 7.6.3) was only seen at the first read, as a 401. | A refused read names the API and its host; the login goes through `/api/v2/authentication`, a refused one says why as FortiOS tells it, and one that sets no session cookie is refused before any read. | `api::tests::refused_read_names_the_call_and_the_status`, `api::tests::a_login_the_firewall_refuses_says_why_and_reads_nothing`, `api::tests::a_login_that_opens_no_session_is_refused_before_any_read` |
| A firewall API answer that is not UTF-8 was decoded with replacement characters, which would be written to NetBox as descriptions. | The read fails: `<call>: answer is not UTF-8`. | `api::tests::an_answer_that_is_not_utf8_is_refused` |
| A missing or `null` serial or host name of a firewall became the text `None`, then the serial of the device. | The collection fails (`no serial`, `no host name`, `member without a serial`). | `parser::tests::status_without_host_name_or_serial_stops_the_collection`, `parser::tests::ha_peer_without_host_name_or_serial_stops_the_collection` |
| Two HA members announcing the same host name (the factory default) gave one entry: one serial was lost. | The collection fails, naming the host name. | `parser::tests::two_ha_peers_of_the_same_host_name_stop_the_collection` |
| A usage error (unknown flag, bad value) exited 2, the code of "differences found". | A usage error exits 1. | `cli::tests::a_usage_error_exits_1_not_the_code_of_changes` |
| A lock file that could not be opened (another user's file, missing directory) ended in an unhandled exception. | An error naming the file, exit 1. | `cli::tests::a_lock_file_that_cannot_be_opened_is_an_error` |
| A stdout that could not be written to (closed pipe) ended in an unhandled exception after the writes. | An error on stderr, exit 1. | `cli::tests::a_report_that_cannot_be_written_is_an_error` |

## netbox-ssot (Proxmox)

| Defect in the reference | What netbox-omnisync does | Test |
|---|---|---|
| A guest agent too old for `guest-get-osinfo` answers 200 with an error inside; read as an answer, it would say "this system reports nothing". | The system information is unknown, and the platform NetBox holds is kept. | `tests/collection.rs` |
| A refused `/cluster/status` was swallowed and the cluster silently named after the source. | Any failed call fails the collection, naming the path: a partial cluster would make the run delete what was not read. | `tests/collection.rs` |
| The interfaces of stopped containers were asked for, and their `lo` kept. | Only running guests are asked; `lo` is left out, as for virtual machines. | `tests/collection.rs` |
| The virtual disks of a machine came out in a random order (iteration over a map). | Sorted by bus, then index. | `collect::tests` |
| A missing `cpus` or `maxmem` became 0. | The collection fails, naming the path. | `tests/collection.rs` |
| Of several PTR records the first one was written as the resolver gave it: with a round-robin answer the DNS name changed from one run to the next. | The first in alphabetical order of the names NetBox takes. | `inventory::dns::tests::among_several_names_the_first_in_alphabetical_order_is_kept_whatever_the_order_of_the_answer`, `dns::tests::among_several_records_the_same_one_is_kept_whatever_their_order` |
| The DNS name was written with the case of the PTR record, where netbox-sync lowered it: one name, two spellings in the same NetBox. | In lower case. | `translate::tests::the_dns_name_is_written_in_lower_case` |
| The DNS name was sent as the resolver gave it, whatever it held: a name NetBox refuses (a space, an empty label, more than 255 characters) made NetBox refuse the address with it. | Such a name is not written, NetBox keeps the one it has, and one warning per source lists them. | `translate::tests::a_name_netbox_would_refuse_is_not_reported_and_all_of_them_give_one_warning` |
| Link-local and loopback addresses were looked up like the others: no resolver names them, and each cost up to two seconds. | Never looked up. | `translate::tests::a_link_local_or_loopback_address_is_never_looked_up` |
| The primary address of a guest was the first one of its family the agent listed, link-local and loopback included: a Windows guest that lists the APIPA address (`169.254.x.x`) of a disconnected adapter first, or any guest with an `fe80::` address and no other IPv6 one, got it as primary, over the address it is reached at. | A link-local, loopback or unspecified address is synced but never primary: the first other one is, or none. | `translate::tests::a_link_local_or_loopback_address_listed_first_is_never_the_primary_one`, `translate::tests::a_guest_with_only_link_local_addresses_declares_no_primary_one` |
| A tag created from a Proxmox tag carried no mark telling it from one set by hand: once Proxmox stopped tagging a guest with it, NetBox kept it on the guest, and the checks it drives went on. | A tag the tool creates carries the `netbox-omnisync` marker in its description, and leaves a guest Proxmox no longer tags with it; a tag netbox-ssot created gets the marker by editing its description in NetBox. | `translate::tests::the_tags_of_a_vm_are_reported_and_only_have_to_exist`, `reconcile::tests::tags_from_the_source_are_managed_and_any_other_tag_is_left_alone` |
| Addresses were looked up one after the other, two seconds each at most: a resolver that stopped answering cost two seconds per address, minutes on a cluster. An address two sources hold was looked up by each. | At once, fifty in flight, three seconds each and fifteen for a source; an address is asked once in a run. | `dns::tests::a_thousand_lookups_run_fifty_at_a_time_and_take_twenty_times_one`, `dns::tests::a_resolver_that_never_answers_costs_the_budget_and_one_warning`, `dns::tests::an_address_two_sources_report_is_asked_once` |

## netbox-sync (VMware)

Not audited before this port: see `vmware-reference.md`. Each rule of that
inventory was checked against the Python source before it was implemented;
what is not reproduced is listed here. The tests are those of the VMware
crate: `translate::tests` in `src/translate.rs`, and `tests/translation.rs`
and `tests/collection.rs` on the recorded answers of a vCenter 6.7.

| Defect in the reference | What netbox-omnisync does | Test |
|---|---|---|
| The addresses of a machine whose VMware Tools do not run (powered off, tools stopped) were not declared: they lost the tag of their source and were marked orphans, and would be deleted with pruning. | They are unknown, not gone: what NetBox holds is kept. | `translate::tests::a_machine_whose_tools_do_not_run_keeps_the_addresses_netbox_has`, `a_stopped_vm_of_6_7_keeps_what_netbox_knows_of_its_addresses` |
| A machine vCenter reports without `config` (inaccessible: its datastore is away) was skipped, and its NetBox object became an orphan with everything under it. | The machine is kept as NetBox has it, its interfaces, addresses and disks are unknown, and a warning names it. | `translate::tests::a_machine_without_configuration_is_kept_as_netbox_has_it` |
| A machine whose host, a host whose cluster, a cluster whose datacenter could not be found was skipped with a log line: its NetBox object became an orphan. | Such an object cannot even be named in NetBox, so it cannot be protected: the translation fails, naming it, and nothing is synced from that vCenter. | `translate::tests::a_machine_that_cannot_be_placed_stops_the_translation`, `translate::tests::a_host_or_a_cluster_that_cannot_be_placed_stops_the_translation` |
| Among the machines of one name in one cluster, the first one vCenter listed was synced (the running ones first): an order nothing guarantees. | The running one, then the lowest managed object number (the oldest machine), whatever the order of the listing. | `translate::tests::the_order_vcenter_lists_homonyms_in_decides_nothing`, `among_homonyms_the_running_then_the_oldest_machine_is_synced` |
| What vCenter did not report was written as a default: a status `offline` without connection or power state, a memory of 0, a disabled network card, a disk of size 0, a platform named `None None`, a CPU custom field `36 None`. | Nothing is written: NetBox keeps what it has. | `translate::tests::what_a_host_did_not_report_is_not_written`, `translate::tests::what_a_machine_did_not_report_is_not_written`, `translate::tests::a_disk_is_described_by_its_mode_its_provisioning_and_its_file` |
| When the tools of a machine told no system (powered off before they ever reported), the system of its configuration replaced, at every run, the one the tools had reported earlier. | The configured system only fills a machine that has no platform. | `translate::tests::the_platform_of_a_machine_is_what_its_tools_report` |
| A disk that does not say how it is provisioned (no `thinProvisioned`) was described as `ThickProvisioned`. | The provisioning is left out of its description. | `translate::tests::a_disk_is_described_by_its_mode_its_provisioning_and_its_file` |
| A machine that reports no disk at all kept the virtual disks NetBox had for it. | It has none: they are orphans like any other. | `translate::tests::a_machine_whose_devices_were_not_reported_keeps_what_netbox_has` |
| The marker of a tag made from vSphere (`NetBox-synced` in its description) was written on any NetBox tag of that name, one made by hand included; that tag was then removed from every device and machine vSphere does not tag with it. | A tag NetBox already has is never rewritten: the marker is only written on a tag the tool creates. | `translate::tests::a_tag_netbox_already_has_is_never_rewritten`, `the_tags_of_6_7` |
| `vm_tag_source = cluster` gave nothing: the cluster was looked for above the folder of the machine, where only folders and the datacenter are. | The tags of the cluster of the host the machine runs on are its tags. | `translate::tests::a_machine_carries_its_tags_those_of_its_cluster_and_those_of_its_datacenter` |
| When the tagging API could not be reached, tag sync was silently off for the run, and every tag made from vSphere was removed from the machines. | The collection fails: nothing is synced. | `tags_that_cannot_be_read_fail_the_collection` |
| An interface that reports no VLAN (a port group without VLAN id) was given the VLAN of the NetBox prefix of one of its addresses. | Nothing is said of a VLAN vCenter did not tell: NetBox keeps what it has. | `translate::tests::a_vmkernel_interface_on_a_port_group_without_vlan_is_an_access_port_without_vlan` |
| An empty `prettyName` in the details of the guest tools gave a platform without name, which ends in an unhandled exception. | An empty `prettyName` is none: the next source of the system is used. | `translate::tests::the_platform_of_a_machine_is_what_its_tools_report` |
| A host or a machine NetBox did not know by name was looked for by its MAC addresses among **every** NetBox interface: a device or machine made by hand, one of another source, or one still reported under its own name in the same run (a clone that kept the generated address of its template) could be taken, renamed and rewritten. | Only an object a tool holds for that very source, that no reported object has by name, and for a machine in the same cluster, can be recognised. Tests of the reconciliation, in `omnisync-core`. | `inventory::reconcile::tests::an_object_no_tool_holds_for_the_source_is_never_a_candidate`, `…::an_object_of_another_source_is_never_a_candidate`, `…::an_object_another_reported_one_matched_by_name_is_never_a_candidate`, `…::a_virtual_machine_of_another_cluster_is_never_a_candidate` |
| A vendor was mapped to `Nvidia` when its name held `nvidea`, a typo no vendor writes: NVIDIA hardware kept `NVIDIA Corporation`. | A name holding `nvidia` is `Nvidia`. On a first run, a manufacturer netbox-sync left as `NVIDIA Corporation` is reported again as `Nvidia`. | `inventory::hardware::tests::nvidia_hardware_is_named_nvidia` |
| A PTR name holding an underscore was refused, though NetBox takes it; a name with an empty label or longer than 255 characters passed the check and was refused by NetBox. Each refused name was a warning of its own, at every run. | The check is the one of NetBox (letters, digits, hyphens and underscores in labels, 255 characters); the refused names of a source are one warning. | `inventory::dns::tests::netbox_takes_letters_digits_hyphens_and_underscores`, `inventory::dns::tests::a_name_netbox_would_refuse_is_refused`, `inventory::dns::tests::refused_names_are_not_reported_and_told_in_one_warning` |

Also not reproduced, as they write objects the source does not describe: the
`vm_role` flag forced on a role named `Server` at every run, and the comments
written on a site named `vCenter: <source>`.
